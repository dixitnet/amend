# amend.ink v2 : lots du 11/11/2026 (comparaison v1 / v2, points « maintenant »)

Statut : **lancé** sur demande de Sylvain (11/11/2026 : « Lancer 1, 3, 4, 6, 8 […] 13, 14. Ajouter zoom », puis « maintenant » pour 18, 19, 20). Source : `docs/v2-comparaison-v1-v2-2026-11-10.md`, § 6.

Docs lu dans son code : `suitenumerique/docs`, commit `8918bd2` (10/11/2026). Chemins : `BE` = `src/backend/core`, `FE` = `src/frontend/apps/impress/src/features`, `YH` = `src/yhub-server/src`.

Règle de design pour tous ces lots : composants de Mantine et de BlockNote **tels quels**, sans valeur nouvelle ; tout réglage qui manquerait est une question pour Sylvain, pas une valeur choisie par Claude (règle 18, ADR 0008). Un lot de design (`v2/design/`) puis un lot technique, chaque fois.

## A. Date de modification, tri, corbeille, dupliquer (points 3, 4, 20)

**Docs.**
- Date de modification : y/hub prévient Django à chaque compactage qui trouve du neuf (`YH/server.ts`, événement `docUpdate` du travailleur, branche `main` seulement) par `POST /documents/{id}/content-updated/` (`YH/backend.ts`, `touchDocument`, sans attendre, « au mieux ») ; Django met à jour `updated_at` et trie ses listes dessus.
- Corbeille : suppression douce (`deleted_at`) ; dans y/hub, `DELETE …/ydoc` **sans** `hard` (pose une pierre tombale, déconnecte les clients, garde le contenu) ; restauration par une route à eux, `restore-ydoc` (`YH/api.ts`, `createApiEndpoint`, réservée au jeton du serveur), parce que y/hub ne l'expose pas ; délai `TRASHBIN_CUTOFF_DAYS` = **30 jours** (`impress/settings.py`) ; liste « corbeille » des documents dont on est propriétaire.
- Dupliquer : `POST /documents/{id}/duplicate/` (`BE/api/viewsets.py`) ; titre « {titre} (copie) » ; le contenu de `main` lu dans y/hub puis écrit dans le nouveau document, attribué à la personne ; sans les accès (sauf option), sans favori ; les pièces jointes ne sont pas recopiées, la copie garde le droit de lire celles que son texte cite.

**Nous.**
- Date : même montage. `worker.events.docUpdate` existe dans notre y/hub 0.10.1 ; le processus de collaboration prévient le serveur (`POST /api/interne/modifie`, jeton interne), qui écrit `documents.modifie_le`. **Écart** : on compte aussi la branche des suggestions (une relecture fait avancer le document ; Docs n'a pas de suggestions).
- Tri : « modifiés récemment » d'abord, puis par titre, puis « créés récemment », dans le volet « Documents » ; l'accueil ouvre le dernier document **modifié** quand le navigateur n'en garde aucun.
- Corbeille : comme Docs, 30 jours, propriétaire seul ; un document à la corbeille disparaît pour tous et refuse toute connexion (pierre tombale de y/hub + droit refusé par notre serveur) ; « Restaurer » et « Supprimer définitivement » ; purge automatique après 30 jours. La route `restore-ydoc` est ajoutée à notre adaptateur y/hub comme chez Docs.
- Dupliquer : comme Docs, le texte seulement (ni suggestions, ni commentaires, ni accès), rangé à côté de l'original pour qui duplique ; il faut pouvoir écrire dans l'espace d'arrivée.

## B. Images envoyées et stockées (point 1)

**Docs.** `POST /documents/{id}/attachment-upload/` (`BE/api/viewsets.py`, `attachment_upload`) : nom aléatoire, stockage objet, clé ajoutée à `document.attachments` ; lecture contrôlée par `media-auth` : on lit une image si on peut lire **un** document dont la liste `attachments` contient sa clé ; antivirus (renoncé ici, renoncement n° 20). Côté éditeur : `uploadFile` de BlockNote.

**Nous.** `uploadFile` de BlockNote ; `POST /api/documents/:doc/images` (qui écrit, ou suggère : un correcteur peut proposer une image), images seules (PNG, JPEG, GIF, WebP, contrôle des premiers octets), taille plafonnée ; fichiers sur disque (`V2_DONNEES/images/<doc>/<nom>`, sauvegardés avec le reste) ; lecture par `GET /api/documents/:doc/images/:nom` à qui peut lire le document. **Écart** : pas de liste `attachments` ni de recopie au collage dans ce lot ; une image collée d'un autre document reste lisible par ceux qui lisent l'autre document (comme la v1). La recopie (« point 1 » de la comparaison) est notée pour un lot suivant.

## C. Éditeur et exports (points 6, 8, 18, 19, zoom)

- **6, table des matières.** Docs n'en fait pas (aucune dans `FE/docs/doc-export` ; son bloc `/children`, non publié, liste des sous-documents). Décision de Sylvain (11/11/2026, Q-toc) : « donner le choix (idem v1) » de la profondeur, et « pouvoir l'insérer où on veut ». Donc, comme la v1 : un **bloc « Table des matières »** du texte (bloc sans contenu de BlockNote, `createReactBlockSpec`, propriété `profondeur` de 1 à 5, défaut 2), inséré par le menu « / » ; à l'écran, la liste vivante des titres jusqu'à cette profondeur ; dans le PDF, `#outline(depth: n)` à sa place, titre traduit ; dans le Markdown, la liste des titres. **Lève le renoncement n° 5.**
- **8, compteur.** Docs : « Word count: N words » dans le menu « … » du document (`FE/docs/doc-management/components/DocToolBox.tsx`, `getWordCount` : texte du document découpé aux blancs), annoncé aux lecteurs d'écran. Nous : même place, **signes espaces compris** d'abord, puis mots ; texte de base (sans les suggestions en cours).
- **18, saut de page.** Docs : `withPageBreak` et `getPageBreakReactSlashMenuItems` de BlockNote (`BlockNoteEditor.tsx`, `BlockNoteSuggestionMenu.tsx`). Nous : pareil ; rendu `#pagebreak()` dans le PDF, ignoré dans le Markdown.
- **19, exposant.** Ni BlockNote ni Docs ne l'ont. Nous : un style en ligne `exposant` (`createReactStyleSpec`, rendu `<sup>`, aucune classe), bouton dans la palette de mise en forme, rendu `#super[]` dans le PDF et `<sup>` dans le Markdown. Picto Tabler `IconSuperscript`.
- **Zoom.** Docs n'en a pas (le zoom du navigateur). Nous : un réglage par navigateur (comme la v1, `reglagesAffichage.js`), qui agrandit le texte de l'éditeur seulement. Décisions de Sylvain (11/11/2026) : paliers **50, 100 et 150 %**, réglage dans le **menu « … »** du document (trois formats).

Fait (11/11/2026, trois commits : technique, design, application) : bloc « Table des matières » (extension `extensions/tableDesMatieres/`, profondeur 1 à 5 sur le bloc par un `<select>`, liste vivante, `#outline(depth: n)` en PDF, liste des titres en Markdown) ; saut de page de BlockNote (menu « / », `#pagebreak()`, absent du Markdown) ; style « exposant » (`extensions/exposant/`, `<sup>`, bouton après le barré, `super()` en PDF, `<sup>` en Markdown) ; compteur en pied du menu « … » (signes espaces compris puis mots, texte de base, à l'ouverture du menu) ; zoom 50, 100, 150 % dans le menu « … » (choix coché, gardé dans le navigateur ; réglages `zoom.*` et `css.editeur.zoom`, ADR 0008). Questions de design : pictos proposés (exposant `IconSuperscript`, table `IconListDetails`, zoom `IconTextSize`, coche `IconCheck`) ; apparence du bloc « Table des matières » à l'écran (titre, choix, liste sans retrait par niveau : `data-niveau` posé, aucun réglage) ; titre de la table dans le PDF, celui de Typst pour `lang: "fr"` (« Table des matières »), ouvert en belle page par notre règle des titres de niveau 1.

## D. Suppression du compte (point 13)

**Docs.** Pas de suppression par la personne : seulement l'administration Django (rapprochement, transfert, v6.0.3). **Écart** voulu (RGPD, et v1). Nous : règle de la v1 dans le domaine. Aperçu document par document : supprimé (je suis seul propriétaire et personne d'autre n'y a accès), confié (un autre éditeur devient propriétaire), quitté (un autre propriétaire existe) ; refus si un document que je possède seul n'a que des lecteurs ou des correcteurs ; équipes : refus si je suis le dernier gestionnaire d'une équipe qui a d'autres membres. Confirmation par la saisie de son adresse. Les documents supprimés vont à la corbeille ? Non : la personne disparaît, ses documents seuls sont supprimés définitivement.

## E. Accueil public et aide (point 14, « page statique »)

**Docs.** Page d'accueil dans l'application (`FE/home`), aide par un lien externe réglable (`HelpMenu.tsx`, `theme_customization.help.documentation_url`). Nous (décision : pages statiques, sans compte, servies par Caddy) : dossier `v2/exploitation/site/` (accueil, aide), servi par Caddy à la bascule ; lien « Aide » du menu du compte vers l'adresse réglée (`V2_AIDE_URL`). Les textes de l'accueil et de l'aide sont à écrire avec Sylvain : le lot pose la page et son montage, avec le texte d'accueil de la v1.

**Fait (11/11/2026).**
- `v2/exploitation/site/index.html` (accueil : texte public de la v1, sans la liste d'attente, « L'accès se fait sur invitation », « Se connecter ») et `v2/exploitation/site/aide/index.html` (aide : les fonctions de la v2 vérifiées dans le code et `i18n/fr.json`, passages marqués « [À relire] »). HTML seul, sans script ni ressource externe, **sans feuille de style** : le contrat statique interdit toute feuille hors de `design/feuilles/` et toute valeur non décidée ; les pages ont l'apparence par défaut du navigateur (clair et sombre).
- `v2/exploitation/prod/Caddyfile.site` : bloc **non branché** pour www.amend.ink (statique depuis `/opt/amend/site`, en-têtes de sécurité de la v2, politique de contenu fermée, HTML en `no-cache`, HSTS de 7 jours, `amend.ink` redirigé vers www). Non validé par `caddy validate` (Caddy absent de l'environnement de Claude).
- Entrée « Aide » du menu du compte (picto Tabler `IconHelp`, rôle `aide`) vers `V2_AIDE_URL`, rendue par `/api/config` seulement si c'est une adresse http(s) absolue sans identifiants (`adresseAide`, domaine) ; sans réglage, pas d'entrée. S'ouvre dans un nouvel onglet.
- À la bascule : copier `v2/exploitation/site/` dans `/opt/amend/site` depuis `deploy/auto/maj.sh` (quand `v2/exploitation/site/` change), remplacer le bloc www.amend.ink du Caddyfile par `Caddyfile.site`, poser `V2_AIDE_URL=https://www.amend.ink/aide/` dans `/opt/amend/v2.env`. Les pages publiées de la v1 (`/p/…`) cessent alors d'être servies.
